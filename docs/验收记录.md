## 复验

先在仓库根目录运行 `npm run build && npm run check && npm test`。使用已安装 DSH 的 CLI 入口运行真实 SDK 合约测试：

```sh
DSH_ENTRYPOINT=/absolute/path/to/@deepseek-ai/dsh/lib/bin.js node --test tests/*.integration.mjs
```

原生复验脚本要求 Node 24、可用的 pnpm 和上述明确版本的 DSH。脚本仅创建隔离临时 profile，使用回环地址、本地模型替身，不读取用户 profile；安装完成后执行原生卸载。下面是 POSIX shell 示例：

```sh
# 安装、启动、鉴权与卸载；不尝试会话或浏览器
DSH_CLI_PATH=/absolute/path/to/@deepseek-ai/dsh/lib/bin.js node tests/native-acceptance.mjs --install-only

# 修复/升级兼容基线后，先复验原生会话 API，不报告 UI 通过
DSH_CLI_PATH=/absolute/path/to/@deepseek-ai/dsh/lib/bin.js node tests/native-acceptance.mjs --api-only

# 完整 UI 验证：需测试环境另有 Playwright 与可运行的 Chromium
DSH_CLI_PATH=/absolute/path/to/@deepseek-ai/dsh/lib/bin.js node tests/native-acceptance.mjs
```

测试用 Playwright/Chromium 不是插件运行时依赖，也不会被安装到用户的 DSH。可通过 `DSH_ACCEPTANCE_OUTPUT` 指定临时证据目录；不要发布整个目录、profile、Cookie 或日志原文。
